Summary

What: a public repo that CU2 calls "examiner-grade patterns for running a credit union on AI agents". Today it ships two offline Python gates (sanitize, theater), a third gate for pnpm overrides, six ranked principles, five agent archetypes, five worked skills and two security notes. CU2 itself runs the gates across its repos (level 4 under X1).

Who for: CU2 engineering today: the gates run in CU2 repos. The audience its own spec states (credit union CEOs, CTOs and CUSOs) is a publication aim, not a recorded use. It is free, not sold, and internal tier (Product: Delivery tooling); funding the publication program is D1.

Where it is: 17 features: 2 at level 4, 5 published (3), 5 tested (2), 4 not published (0), 1 unverified. The credit-union-specific content in the repo's own spec (workflow specs, R1-R5 standards, examiner-facing archetypes, landmines) is not published, and nothing in the repo maps to what an examiner expects.

Active phase: P0 Make the front door true. No dates: the repo has no milestones and none was given.

Decision that matters most: keep the "examiner-grade" claim and substantiate it, or reword it now (D2). NCUA's own page says it has issued no AI-specific rules.

Problem and positioning

The job a credit union hires it for, in the buyer's words: "show me how to run AI agents without a control quietly lying to me, and give me something I can put in front of an examiner." The job its engineers hire it for: "stop a repo leaking internal context, and stop a CI check from passing when it did not run."

For credit union and CUSO technology and risk leads who must run AI agents under exam scrutiny, cu-agent-standards is an open pattern library with runnable gates that turns each lesson into a check that fails first and a ledger that admits its own mistakes. Unlike governance frameworks and platforms, we publish working code and incident-derived patterns, not policy templates or a platform. (Competitors were not sized: internal tier.)

Honest gap: the "unlike" holds for the gates and the ledger. It does not yet hold for credit-union regulatory content, which is the part the tagline promises (section 6, section 13).

Relationships. cu2-standards: CU2's internal standards (served by cu2-mcp); its spec docs/cu-agent-standards-SPEC.md (v1.0.0, 2026-07-28) is this repo's plan of record and is carried forward in P2 to P4. The gates moved out of cu2-standards into this repo (cu2-standards tools/theater-README.md). Marshal: not a Marshal component (X4 does not apply). Marshal's examiner-evidence use case (UC7 in the Marshal roadmap) could cite these patterns as public method; today nothing in this repo is examiner evidence, so that link is a decision (D6), not a fact.

Regulatory and risk surface

  • Claims to examiners and regulators (accuracy). NCUA's AI resource page (updated 11/18/26) says NCUA has issued no AI-specific rules and that existing, technology-neutral rules apply. Nothing in this repo may say a rule requires, or an examiner accepts, a pattern unless a citation backs it. "Examiner-grade" is a claim of that kind and has no mapping behind it today (RK-1).
  • UDAAP, ECOA and Reg B, FCRA, BSA. P2 would publish workflow specs for adverse action, fair lending and BSA/AML. The repo holds no member data; the risk is a wrong citation or a stale one being read as guidance (RK-4). Which consumer-protection rules bind CU2 as a publisher, as opposed to the credit unions that use the text, is a question for Hugh and counsel; I did not decide it.
  • Marketing accuracy. Counts and claims in the README are published statements. The ledger count is CI-checked; the estate figures (774 candidates, 92 repos) are not and cannot be reproduced from the repo (README says so).
  • Licensing. The LICENSE file is MIT with an MIT notice for adapted third-party code. GitHub's API reports the licence as "Other" (NOASSERTION). The spec calls for MIT for code and CC-BY-4.0 for prose; the repo is MIT only. See RK-3.
  • Stale guidance. NIST says the AI RMF is being revised; the NCUA page changed on 11/18/26; the GAO (May 2025, second-hand from search) said NCUA's model risk guidance is limited for AI. Every dated reference needs a re-check date (RK-4).
  • Member data: none held; the repo's own sanitize gate keeps it out. ADR-031 checklist: not applicable. Sub-processors: GitHub only (subprocessors.yml id github, cu2-standards origin/main, read 2026-11-21); the npm registry call in hop 4 has no row (low, no member data).
